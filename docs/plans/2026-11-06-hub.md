# Hub plan

The hub copies Theo Browne's setup as closely as we can: one always-on machine at home holds every Claude and Codex login, keeps them fresh, and serves the rest of the fleet from one residential IP. Theo's [hub guide](https://gist.github.com/t3dotgg/59a521d2ee8d70aaf90e280c175072af) and [video](https://www.youtube.com/watch?v=D8PikZ1KhUo) are the baseline; where this plan differs, it says so. Vocabulary is in [`GLOSSARY.md`](../../GLOSSARY.md); the decisions are in [ADR 0003](../adr/0003-hub-is-a-fork-of-cliproxyapi.md) and [ADR 0006](../adr/0006-hub-copies-theos-setup-on-the-official-bases.md).

## What runs where

| Piece | Where |
| --- | --- |
| Hub machine | `cachy`, on a TELUS home connection, never sleeps (sleep targets masked), linger on |
| Proxy | [joshmeads/prox](https://github.com/joshmeads/prox) (private), a fork of CLIProxyAPI at v8.0.76 plus the official management panel v1.28.1 as `web/` |
| Install | `~/cliproxyapi` (binary, `config.yaml`), logins in `~/.cli-proxy-api`, `cliproxyapi.service` user unit, all from `hub/install.sh` |
| Reach | Port 8317 on the LAN (ufw admits the home subnet only) and the tailnet (`http://cachy:8317`). Nothing else. |
| Secrets | `HUB_ACCESS_KEY` and `HUB_MANAGEMENT_KEY` in fnox; the config is rendered from them once |
| Clients | `hub/client.sh` writes `~/.claude-hub` and `~/.codex-hub` beside the direct homes, and `claude-hub`, `codex-hub` and `claudex` wrappers |
| Usage ledger | In progress: ClickHouse in Docker on `cachy`, fed live by the hub and backfilled from transcripts |

## Config

`hub/config.yaml.tmpl` is Theo's config with three differences: the hub listens on every interface because ufw limits it to the LAN and the tailnet, routing is `soonest-reset-first` (his fork's feature) instead of round-robin, and quota history is on for the panel's charts.

Theo's two rules stand: never serve anyone else's traffic, and use the Claude subscriptions only from Claude Code.

## The fork

- Built from the official bases: upstream CLIProxyAPI and upstream's own panel, because both stay current and merge cleanly.
- Most hub features are ported from [rune-oai/t3code-proxy](https://github.com/rune-oai/t3code-proxy) (MIT), the closest public copy of Theo's fork: soonest-reset-first routing with plan weights and a 5-hour headroom guard, quota history, routing of models newer than the catalog (the problem Theo hit on Nov 9), provider-scoped endpoints, the embedded panel, and `doctor`. Its Go module rename and rebranding were undone.
- Its panel diverged too far to merge (it changed 468 of the official panel's files), so `web/` stays official and the prox look is being built as add-on files: a dark theme override, a Quota Management page with pooled recorded and projected burn, and per-account windows. `web/PROX.md` will list the official files they hook into.
- Merge rules, the seam list and the upgrade steps are in the prox repo's `HUB.md`. Its `hub/upstream-check.sh` trial-merges the newest releases and runs every check, and its `hub/forkcomments` fails on any comment the fork adds.

## Accounts

The owner signs in on `cachy`, from `~/cliproxyapi`, or through the panel's OAuth Login page:

```sh
./cli-proxy-api -claude-login           # each Claude subscription; callback on port 54545
./cli-proxy-api -codex-device-login     # each Codex account (personal, work)
```

Today that is one Claude, a second soon, and two Codex. Soonest-reset routing and the pooled charts start to matter from the second account of a provider. To bench an account, set `"disabled": true` in its auth file.

## Clients

`hub/client.sh` on each machine, with `HUB_ACCESS_KEY` in that machine's fnox. It uses `http://cachy:8317` off the hub; the VM, which does not resolve `cachy`, passes the hub's LAN address, `http://<hub LAN IP>:8317`. The direct `~/.claude` and `~/.codex` stay untouched, because Claude Code loses claude.ai connectors and Remote Control under a gateway token. The hub homes link the direct homes' instructions, skills, agents and plugins, copy the user-level MCP servers, and add:

- Claude Code: `ANTHROPIC_BASE_URL`, `ANTHROPIC_AUTH_TOKEN` and `"promptCacheTtl": "1h"`. Without the last one Claude Code drops to a five-minute cache through any custom base URL.
- Codex: a `prox` model provider with `wire_api = "responses"`, `supports_websockets = true` and the access key.
- `claudex`: GPT Sol inside Claude Code through the hub, as in Theo's alias.

Both wrappers set both homes, so an external lane started from a hub session also goes through the hub. The hub configs are copies: rerun `hub/client.sh` after changing the direct settings, and changes made inside a hub home (permission allows, `/model`) are replaced on the next run. T3 Code uses a Claude provider instance with `~/.claude-hub` and Codex with "Use existing CLI" on `~/.codex-hub`; its pooled limits come from Settings > Providers > Usage providers > Add hub, with the bare hub URL and the management key.

## Usage ledger

Theo logs every proxied request into ClickHouse and has agents query it. Ours records counts and structure only, never prompt or response text: per request the account, model, tokens in and out, cache reads and writes, latency and time to first token, session and parent session, and the tool calls, skills and subagent types involved. The hub feeds it live through upstream's in-process usage hook. A backfill fills history from Claude Code transcripts, Codex session logs and T3 Code's database on each machine, into the same tables.

## Fleet

Fleet management moves into ai-stack, so the hub, the client homes, the backfill and machine setup work together: a new machine gets `hub/client.sh`, its transcripts are backfilled, and `ai-stack fleet` checks it.

## Build order

1. **Hub (done).** Fork, port, panel subtree, install, LAN and tailnet reach, `doctor` clean apart from accounts.
2. **Accounts.** The owner's logins. Then check soonest-reset picks, session affinity (cache reads against writes per session), and Codex over websockets with a real account.
3. **Panel look.** The prox theme and Quota Management page.
4. **Usage ledger.** ClickHouse, the live sink, the backfill on `cachy`, then the Mac and the VM.
5. **Clients on every machine.** Mac (`~/.codex`, `~/.codex-personal`, `~/.codex-work`), the VM, and T3 Code instances.
6. **Fleet in ai-stack.**
7. **Later:** Cursor pass-through ([ADR 0005](../adr/0005-cursor-passes-through-the-hub.md)), access keys limited to providers ([ADR 0004](../adr/0004-access-keys-are-limited-to-providers.md)), `pi` and `agy` through the hub, and the fork's websocket fixes listed in `HUB.md`.

## Known limits

- If `cachy` is off, every hub session stops; the direct homes keep working.
- Quota reads use undocumented endpoints (`api.anthropic.com/api/oauth/usage`, `chatgpt.com/backend-api/wham/usage`). When a read fails, routing keeps its last ranking.
- The fork holds every token, so each upstream merge is a supply-chain event: merge deliberately and read the diff.
- This might get the accounts banned; the owner accepts that risk, as Theo's guide warns.
