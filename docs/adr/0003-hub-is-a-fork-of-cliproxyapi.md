# The hub is a fork of CLIProxyAPI that keeps merging upstream

The hub needs behaviour that a stock proxy cannot give: soonest-reset routing, access keys limited to providers, session bindings that survive a restart, a usage ledger, a dashboard, and a Cursor pass-through. We fork [CLIProxyAPI](https://github.com/router-for-me/CLIProxyAPI) and keep merging upstream, as Theo did for routing. We rejected a sidecar around a stock binary, because it could steer only by polling, could not limit keys, and forced a second proxy process to keep Claude credentials apart. We rejected store plugins, because they run native code beside every token and are built for one proxy version. The cost is merge work: upstream shipped 351 commits touching at least 300 files between v8.0.33 and v8.0.58. So fork code lives in new packages, upstream files change only at a short listed set of seams, the Go module path stays unchanged so imports never conflict, and upgrades are deliberate merges rather than rebases.
