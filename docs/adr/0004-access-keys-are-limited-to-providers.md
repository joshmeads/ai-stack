# Access keys are limited to providers in one proxy process

Claude subscriptions must be used only from Claude Code. Upstream's access keys reach every credential, and the proxy presents every Claude OAuth request as Claude Code, so real `pi` holding a hub key reached a Claude subscription. The fork gives each access key a list of allowed providers, enforced in `authSelectionEligibility.allows`, which every credential pick already passes through, and a key with no list is refused. We chose this over running one process for Claude and one for everything else. Separate processes give stronger isolation, because no code path can reach a credential the process does not hold, but they double the configs, dashboards and services, and split one quota view in two. A bug in the limit could therefore expose a Claude credential, so the fork keeps a regression test that sends real `pi` with a non-Claude key at a Claude model and expects a refusal with no upstream call.
