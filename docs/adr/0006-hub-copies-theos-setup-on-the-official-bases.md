# The hub copies Theo's setup on the official bases

The owner wants the hub to match Theo Browne's as closely as possible, looks included, while staying easy to update from upstream. So the fork starts from the official CLIProxyAPI release and the official management panel, and ports the features of rune-oai/t3code-proxy, the closest public copy of Theo's private fork, onto them. We rejected adopting t3code-proxy itself: it renamed the Go module, rebranded upstream files and rewrote 468 of the panel's files, so every upstream release would conflict. The port undoes the rename, keeps upstream's text, and adds the panel's look as add-on files on the official panel, which is a git subtree. One access key serves every client, as in Theo's guide; access keys limited to providers ([ADR 0004](0004-access-keys-are-limited-to-providers.md)) wait until a second machine or tool needs a different scope. The hub listens on the LAN and the tailnet only, with ufw admitting the home subnet. Fork code carries no comments, which a lint enforces on every line the fork adds, while upstream's comments stay so merges stay small.
