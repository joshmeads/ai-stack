# Cursor passes through the hub on its own login

The owner wants Cursor CLI traffic and usage visible at the hub without moving Cursor's login there. `cursor-agent` is pointed at the hub with `CURSOR_API_ENDPOINT`, and the hub forwards each request to Cursor unchanged with the client's own token, reading token counts from the stream as it passes. The hub also rewrites the agent host in Cursor's server config, because otherwise the client follows that config and sends its agent stream straight to Cursor. We rejected a Cursor provider that translates to other APIs, because it reimplements a private protocol and would let other clients spend the subscription. We rejected `HTTPS_PROXY` with TLS interception as the main route, because each machine would have to trust a private CA that could read all of its traffic through that proxy. Parsing is best effort: a failed parse never interrupts the stream, and a change to the protocol costs usage records rather than Cursor itself. The dashboard calls Cursor's own usage service as the check on what the stream reported.
