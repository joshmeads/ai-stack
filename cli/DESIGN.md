# ai-stack CLI design

The CLI turns one config into a per-harness setup of the stack: the `jm` plugin marketplace with its one plugin, `pstack`, and the standalone skills of the global groups in `stack.toml`. The plugin carries pstack's skills, agents and hooks; the CLI writes only what differs per user and per harness (the model sheet, the routing block and the owner's global instructions), installs the plugin, links the standalone skills, and cleans up after older installs. It has one install mode: edit in place, idempotently, with `--force` for an unmanaged model sheet or a stray skill in a skill link's way.

## Commands

- `config show [--json]`: print sorted, flattened effective config without writing.
- `init [--force]`: write `config.default.toml` unchanged to the config path with both harnesses enabled, and print detection results. Runtime detection skips missing CLIs.
- `diff [--clean]`: build the plan and print it. Exit 0 when empty, 1 otherwise. Runs only the read-only plugin `list --json` queries.
- `stray [--json]`: build the plan with `clean: true` and report `Plan::stray`: the skill folder entries `links` classified as stray (see Skill folders), as sorted home-relative paths, and the ids of the commands with `clean` set. ai-stack's own links and the removal of stale `jm` plugins never count. Install conflicts and stray counts come from the same classification. It plans with `Options::report`, so no stray tree is fingerprinted and no `git` runs; `apply` refuses a report plan. Warnings, including skip notices, go to stderr so JSON stdout remains parseable. Same read-only queries as `diff`; exit 0.
- `install [--yes] [--force] [--plain] [--clean]`: plan, review (TUI, or plain text plus a y/N prompt), apply. The TUI's `c` toggles clean and re-plans.
- `update [--yes] [--plain] [--bump-models] [--branch B]`: `git pull --ff-only <remote> <branch>` in the stack (`--branch` overrides `stack.branch` for the run), after checking `git symbolic-ref --short HEAD` names that branch (a detached HEAD or another branch is refused), if `cli/` changed, print that nothing was installed and exit 3 before checking models or installing. Rebuild with `cargo install --path <stack>/cli`, then rerun the same command with its original flags. This detects only changes in this pull; it does not persist a pending rebuild or compare the binary with the checkout, so rerunning without rebuilding can proceed with the stale binary. Otherwise optionally bump, load the config against the pulled family table, report models, then install. Before the pull it parses only `[stack]`.
- `models [--bump]`: compare model IDs with the provider catalogs (`codex debug models` under `[harness.codex].home`; the Anthropic Models API or docs page). `--bump` first rewrites exact ids and lanes as families (see Config).
- `skills add|status|update`: vendored skills in `<stack>/stack.toml` (see Skills).
- `groups [--json]`: each group's `global` flag and resolved skills, with a token estimate, then the global set (see Skills).
- `auth status [--json]`: local AI CLI login status, without loading config (see Login status).
- `fleet login <MACHINE> <PROVIDER>`: run one provider’s headless login with inherited terminal streams, then report its status (see Fleet login).
- `fleet init|status|auth|drift|update|switch`: machines in `<config dir>/fleet.toml` (see Fleet).
- `lint [PATH...] [--base REV] [--scope S] [--json] [--fix]`, `lint rules [--json]`, `lint skips [--days N]`, and the hidden `lint hook <harness>`, `lint pre-commit`, `lint post-commit`, `lint jj-fix` and `lint jj-tool --plan FILE PATH`: diff-scoped ast-grep lint (see Lint). Reads only `[stack]` and `[lint]`.

## Config

- `[stack]`: `path`, `remote`, `branch`, `legacy_paths`. `--stack` replaces `path` and moves the configured path into the legacy roots.
- `[harness.<name>]`: `home`, `enabled`.
- `[models.<alias>]`: exactly one of `family` or `id`, optional `provider` (`anthropic` | `openai`) that must agree, optional `efforts`, optional `context`.
- `[leads]`, `[review]`: `"alias@effort"` per harness; effort required, and it must be in the model's `efforts` when set.
- `[skills]`: `prompt_runner` argv, default `claude -p --permission-mode acceptEdits`; optional.
- `[lint]`: `enabled`, `scope`, `disable`, `enable`, `severity`, `ignore`, `skip` (`files`, `hunks`, `lines`, `findings`), `skip_alert` (`percent`, `days`, `min_commits`), and `[[lint.project]]` with `path`, `paths`, `ignore`, `scope`, `enabled`; all optional. `config::parse_lint` deserializes only `[stack]` and `[lint]`.
- `[sheet.claude]`, `[sheet.codex]`: all 15 rows, lanes as descriptors. The accepted rows, panel rows, parent-only rows and writer rows live in constants at the top of `config.rs`. Sheet descriptors are not tied to `[models]`.

The family table is data, not code. `config::Registry::load` reads `<stack>/plugins/pstack/skills/poteto-mode/references/model-families.json` (`FAMILIES_FILE`), which `registry/render.ts --write` generates from `registry/models.ts` and `registry/providers.ts`: each provider with `readOnly`, and each family with `provider`, `name`, `model`, `efforts`, `kept` (model and efforts) and `revisionPrefix` for a Claude rolling alias. Unknown fields are ignored, so the table can grow without a rebuild. `config::parse` reads the TOML and the stack path (with `--stack` applied); `Unresolved::resolve` then checks models, routes and sheets against the table: a family resolves to its current model, an `id` or lane model must be a current model or kept predecessor, efforts come from the table, and a read-only provider is refused on a writer row. `config::load` does both, so every command that loads the config needs the table, and a missing or unreadable table is an error naming its path. A model release is therefore one registry edit outside `cli/`: `update` pulls it, `git diff -- cli` is empty, and the running binary resolves the new model.

`models::bump` parses the config with `toml_edit::Document`, which keeps source spans, and replaces only the spans of `id` keys and values under `[models]` and of Claude and Codex lane strings under `[sheet]`, keeping each string's quote style. It checks the result with `parse(...).resolve(...)` and returns an error, naming the entries it could not map to a family, instead of text that does not load.

`config::flat` validates with the normal loader, then serializes the parsed `ConfigFile` with serde defaults filled in and flattens its tables into `drift::Flat` (`BTreeMap<String, serde_json::Value>`). This uses the file schema because resolved `Config` expands paths and drops disabled harnesses. Paths stay exactly as written, including `~`; absent optional model fields stay absent. Only `config.toml` sections are flattened. This config contains no secrets. `--stack` is an execution override and does not alter the stored-config view.

## Plan

`install::plan(cfg, opts, runner)` first filters enabled harnesses through `Runner::available`, adding a skip notice to `warnings` for each missing CLI. A command-scoped `SystemRunner::detect()` captures absolute executable paths on `PATH` once, using the same current-user `access(X_OK)` check as auth; TUI replans and apply spawn those paths. Tests inject availability through `FakeRunner`. The effective config excludes missing harnesses. The folder index registers skipped harness roles and their routes alongside active roles. Cleanup-only folders inside skipped routes are excluded. Active links folders retain their roles, while individual entries that hold or route into skipped harnesses are protected, including absent wanted destinations. If every enabled harness is skipped, the plan is empty and succeeds. Explicitly disabled harnesses get no skip protection from independently configured clean roots. Otherwise it loads and validates `<stack>/stack.toml` (an invalid file fails the plan), builds `links::Owner` once, then returns a `Plan` of file actions (`Write`, `Remove`, `Unlink`, `ReplaceWithFile`, `MoveToBackup`, `Link`), plugin `commands`, `conflicts`, `warnings` and `stray`. Resolved writes to a sheet, instruction file, settings file or link ledger inside a skipped route are conflicts naming the requested and resolved paths. For each available enabled harness:

1. **Sheet.** `<home>/pstack-models.md` from `render::sheet`. First line `render::MANAGED_MD`; setup-stack's managed-sheet check matches its `<!-- Managed by ai-stack` prefix. Absent or managed: write if changed. A symlink into the stack or a legacy root (`Owner::owns`): replace. Anything else: conflict, or replace with `--force`.
2. **Instruction file** (`Harness::instruction_file`). Resolve a symlink to its target (write-through). Validate markers. Remove `open-pstack:local` and every `ai-stack:*` block except `instructions`, `routing` and `pstack-models`, including the old `anthropic-guidance` block. Claude: remove other `@` lines that resolve to this sheet. Upsert `instructions` from `<stack>/instructions/common.md` and `<stack>/instructions/<Harness::instructions_stem>.md` (each trimmed, blank or absent skipped, joined by a blank line), or remove it when both are absent; a source containing an `<!-- ai-stack:`, `<!-- pstack:` or `<!-- open-pstack:` marker is a conflict naming the file. The text is always inlined, never `@`-imported, so every harness gets the same mechanism. `instructions/claude.md` carries the Anthropic guidance verbatim and reaches only Claude through `instructions`; no separate guidance block is written. Upsert `routing` (`render::routing`). Claude: upsert `pstack-models` with `@<abs sheet path>`. Codex: upsert the `pstack:models` mirror with the exact sheet bytes.
3. **Hook file** (Claude `settings.json`, Codex `hooks.json`; `plan_hooks`). Write-through as above; an absent file starts as `{}`. Unparsable JSON, a non-object root, `hooks` that is not an object or an event that is not a list is a conflict and the file is untouched. Claude only: remove hook commands that exactly match the old forms (`bash <root>/plugins/pstack/hooks/session-start`, optionally quoted and followed by `| sed 's/pstack://g'`; `python3 <root>/scripts/task-context.py`, optionally quoted) for the stack or a legacy root. A group loses only those commands; a group or event list emptied by the removal is dropped. Then `ensure_lint_hook` makes sure each `LINT_HOOKS` event, `PostToolUse` with matcher `Edit|Write|Bash` and `PreToolUse` with matcher `Bash`, holds one `lint_command(cfg.exe, cfg.exe_flags, harness)`: an existing owned entry (`lint_hook_of`, which also accepts an older `lint hook <harness> post-edit`) keeps its position and gets its `command` rewritten, and its group's matcher set to the event's matcher when the entry is alone in the group; a missing one is appended as a new group with that matcher at the end of the event's list. Entries an older install added under other events are left alone. Nothing is ever removed or reordered, because Codex keys hook trust by `<file>:<event>:<group index>:<handler index>`. For Claude, `merge_claude_env` merges `lint_env` into the `env` object of the same file. For Codex, `plan_codex_env` parses `config.toml` with `toml_edit` (a parse error is a conflict), creates `[shell_environment_policy]` as an implicit table when absent, appends the four `CODEX_INCLUDE` patterns to an existing non-empty `include_only` (an empty one means no restriction to Codex and stays empty), adds them as `"include"` entries to a `filters` table that has an `"include"` entry (comparing keys case-insensitively, as Codex does; a key already there with any other value is a conflict, because Codex applies that allowlist after `set` while its excludes run before it), and merges `lint_env` into its `set` table. `env_edits` is the shared merge: any `GIT_CONFIG_KEY_n` whose value is not one of the four `OUR_GIT_KEYS`, or a `GIT_CONFIG_COUNT` with no `GIT_CONFIG_KEY_n`, is a conflict; ai-stack's own numbered keys beyond the wanted ones are removed; each wanted name whose value differs is set. Written only when something changed. `Config::exe` is `std::env::current_exe()`. Before the harnesses, `plan` runs `git --version` and warns when git is older than 2.54, the first release that runs `hook.<name>.command` hooks from config.

Then, once for all harnesses:

4. **Skill folders** (`links::plan`, below).
5. **Plugins** (`plugins::plan`, after all file actions). Check that the stack's harness manifest (`.claude-plugin/marketplace.json` or `.agents/plugins/marketplace.json`) names `jm` and lists every plugin in `PLUGINS` (only `pstack`); otherwise conflict. When the harness home does not exist yet, plan every command. Otherwise query `plugin marketplace list --json`: absent means add the marketplace and install every plugin; another source is a conflict; the stack means query `plugin list --json`. Every installed `<name>@jm` the manifest does not list gets a removal (`plan_removal`, shared with `--clean`, with `clean: false`) before the installs. Its `undo` is `Restore::Retired`, because no CLI can reinstall a plugin its marketplace dropped. Apply turns it into a note when it writes `removed-plugins.json` (`retired_note`): the newest commit on HEAD's history whose harness manifest lists the plugin and whose tree has a `SKILL.md` under the plugin's source directory. A commit that lists the plugin after its skills moved out cannot restore it, so for `jm-games` and `jm-tools` the note names the parent of `8b08520`. A `git log -S` check skips the walk for a plugin no commit ever named. Then install each missing plugin. Both CLIs record an installed version: when it differs from the checkout's plugin manifest (`.claude-plugin/plugin.json` or `.codex-plugin/plugin.json`), refresh with `claude plugin update <id> --scope user` or `codex plugin add <id>`. Claude's plugin manifest version takes precedence over its marketplace-entry version. Match only user-scope Claude entries (or legacy entries without scope), so a project, local or synced entry cannot mask a missing or stale global install. Refresh leaves disabled plugins disabled. A missing CLI is skipped before planning; a query that cannot start the detected CLI is a conflict naming its captured path; a query that starts but fails is a warning and plans every command (both CLIs treat repeats as no-ops). `CLAUDE_CONFIG_DIR` / `CODEX_HOME` is set on a command only when the harness home differs from what the CLI would use.

With `--clean` (`Options::clean`), `links::plan` adds the stray moves, and `plugins::plan_clean` adds an uninstall (Claude user scope), disable (Claude `synced` scope, which the CLI cannot uninstall) or `codex plugin remove` for every listed plugin `Clean::keeps_plugin` rejects, except `jm` plugins, which step 5 owns. Those commands carry `Restore::Command` undo args and `clean: true`, and come before every install command. Apply records every command with an `undo` in `removed-plugins.json` in the backup dir.

### Skill folders

`links.rs` owns every skill folder ai-stack touches. `index` resolves each folder once with `paths::resolve` and merges folders that resolve alike, keeping the first spelling for actions and the union of their roles: `links` (each harness's user skill folder, `Harness::skill_folder`), `leftover` (each harness's `<home>/skills` and `<home>/agents`), `agents` (`<home>/agents`) and `clean` (each `[clean] skill_roots` entry). A symlinked `~/.codex/skills`, or a `~/.claude/skills` that is `~/.agents/skills`, is one folder with several roles, so no entry is planned twice.

`paths::resolve` has lstat semantics. It walks the path one component at a time, replaces each existing symlink with its target even when that target is missing (at most 40 times, then the rest is taken as written), resolves `..` against what it has resolved so far, keeps missing components as written, and finally canonicalizes the existing prefix, which also gives a case-insensitive disk's spelling. The skill folders, link ownership, the sheet import check and old hook commands all use it, so `/tmp` and `/private/tmp` match everywhere.

`Owner` holds the stack and the legacy roots, resolved once, and the ledger. `target_of` resolves a link target's parent and keeps its last component as written, so a link to `<stack>/skills/<name>` stays a link into the stack when that skill directory is itself a symlink, while `<stack>/escape/../x` leaves through `escape` even when `escape` dangles. A link is ours when the ledger records its path with the same target text, or when `target_of` lies inside the stack or a legacy root.

The ledger is `<home>/.local/state/ai-stack/links.json` (`ledger.rs`): `{"version":1,"links":{<link path>:<target text>}}`, keyed by the folder's resolved path joined with the entry's name. Apply records each `Link` it makes and drops each path it unlinks or moves, applying those changes to the file as it is then, so entries apply did not touch stay, and writes it atomically, also after a failed action. A missing, unreadable or malformed ledger records nothing and never blocks a plan. It is what keeps a link made by `install --stack <other>` ours after that checkout is deleted, and what keeps a link into an unrelated repo stray.

`read` classifies each entry of a folder once, skipping dot entries: `Ours` (a link `Owner` claims, with its target text and resolved target), `Protected` (a directory or file whose resolved path holds the stack or a legacy root), `Skipped` (an entry that holds or routes into a skipped harness, left alone without a stray report), `ManagedAgent` (in an agents folder, a regular file with `render::MANAGED_MD` or a first line of `render::MANAGED_TOML`) or `Stray`. The wanted names are `StackFile::global_skills()` whose `skills/<name>/` exists (a missing one is a warning) in a `links` folder, and none elsewhere. The entry at a wanted name is found by exact name, else by lstat device and inode, so a case-insensitive disk's `HANDOFF` is the entry at `handoff`; a displaced entry keeps that on-disk path for its backup and the action text. `plan_folder` then derives every action:

| Entry | Action |
| --- | --- |
| Ours, wanted, `target_of` is `<stack>/skills/<name>` resolved, same name | none |
| Ours, wanted, other target or other on-disk name | `Link { displaces: OwnLink { entry, target } }` |
| Ours, not wanted, in a `links` or `leftover` folder | `Unlink` |
| ManagedAgent | `Remove` |
| Protected | conflict naming the entry and the checkout it holds |
| Stray, wanted | in `Plan::stray`; a conflict, unless `--clean` moves it (a `clean` folder and `keep_skills` does not match) or `--force`: `Link { displaces: Stray { entry, fingerprint, clean } }` |
| Stray, not wanted, in a `clean` folder, not kept | in `Plan::stray`; with `--clean`, `MoveToBackup { clean: true }` |
| Wanted name absent | `Link { displaces: Nothing }` |

Before any of that, a folder that resolves inside the stack or any legacy root (including the configured checkout during `--stack`) is a conflict and gets no action: `~/.claude/skills -> <stack>/skills` would otherwise move a checkout's own sources. A `links` folder with wanted skills that does not exist because it, or an ancestor, is a symlink to a missing directory is a conflict naming that target. Within a folder the actions run in entry order, then the links in name order. Every folder-entry action carries the folder's `Anchor`: its resolved path and its device and inode (none when it did not exist yet).

The `Runner` trait is the seam for the CLIs. `SystemRunner` runs the absolute paths captured by `detect()` with stdin closed; tests use `plugins::fake::FakeRunner`, which keeps marketplace and plugin state and answers the list queries in each CLI's JSON shape.

## Apply

`plan::apply(plan, backup_root, runner)` refuses on conflicts and on a report plan, re-verifies every file action against the state it was planned from (for a folder-entry action, also that its folder still resolves to the anchored path and is the anchored directory, checked again right before the action runs), backs up each existing target under `<backup_root>/<unix-time>[-n]/{home,abs}/`, applies the file actions, then runs the commands in order. A `Link` verifies what it displaces (`Displaced::Nothing`: the path is absent; `OwnLink`: the same link target at `entry`; `Stray`: the same lstat fingerprint at `entry`) and backs it up as part of the same action: a repointed link is copied into the backup, a stray is moved there, both under the entry's on-disk name. A new link creates its folder. Apply then updates the ledger with the links it made and removed. A failed command stops apply with its stderr; the file changes already made stay, and the next run plans only what remains.

## Skills

`stackfile.rs` owns `<stack>/stack.toml`. `StackFile` is `groups: BTreeMap<GroupName, Group>` plus the vendored `skills: Vec<Skill>` (`[[skill]]`). `Name` (aliased `GroupName` and `SkillName`) is validated when parsed, so it is always one safe path component; `Skill::name` and `Skill::rename` are `SkillName` too, and the CLI parses `--name` and `--move` into it. A `Group` has `global` (default false), `includes` and `skills`. `resolve(groups, roots)` is the pure closure over `includes`, returning each skill once; `global_skills()` resolves every global group. `validate()` checks the file alone: vendored entries (below), unknown includes, include cycles (reported as `a -> b -> a`), a skill listed twice in one group, two members anywhere that differ only by case, and that every vendored skill installed into `skills/` (`Skill::is_standalone`) is a group member. `check_skills_dir(stack)` checks it against the tree: every member is `skills/<name>/` with `SKILL.md` (a vendored member may be missing), and every non-dot directory in `skills/` is in a group. `load` runs both and prefixes errors with the file path; an absent file is an empty one. Every error names the offending key, such as `[groups.games] includes` or `[[skill]] "grill"`. A test loads the repo's own `stack.toml` against its `skills/`.

The `[[skill]]` schema is (`name`, `source`, `path`, `ref`, `commit`, `dest`, `move`, `process` as one-or-many `{type, input}`) and its validation: `[A-Za-z0-9._-]+` not starting with `.` for `name` and `move`; plain relative components for `path` (or exactly `.`), `dest` (no `.git` component, and inside `skills/` only as `skills` itself, both compared without case) and script inputs; no prompt starting with `-`; a valid git ref; one entry per installed directory and per name or installed name, compared without case. The default `dest` is `skills`, which makes a standalone skill. Another `dest` vendors a skill where a plugin reads it; only a hand-written entry has one. `check_dests(stack)` resolves `<stack>/<dest>` with `paths::resolve` and refuses one outside the stack, inside `.git`, or inside `skills/` unless `dest` is exactly `skills`; `load` and `skills add` run it, so a symlink or `.GIT` spelling cannot reach git's refs. `edit(stack, ops)` is the only writer. Its operations are `Op::AddMember` (append to `[groups.<g>] skills`), `Op::PushSkill` (append a `[[skill]]`) and `Op::SetSkill` (set `ref` and `commit` on one named entry). They apply with `toml_edit` to the text read at write time, so concurrent edits to other keys survive. Groups may be tables, dotted keys or inline tables; entries may be an array of tables or an array of inline tables; any other shape is an error. The result must parse, validate and show each operation's change, or nothing is written. The write goes through `paths::write_through` and `plan::write_atomic` with the file's mode. A value keeps its comment. An item appended to a multi-line array goes on its own line with the last item's indentation, the last item gets a comma, and a comment that trailed it stays on its line. A new entry leaves out `ref` and `dest` at their defaults. There is no stack-level stamp; the stack's own history is its git log.

`skills.rs` resolves a ref with `git ls-remote` (peeled tag, exact name, `refs/heads/`, `refs/tags/`; a 40-hex ref is used as is), fetches the commit into a throwaway repo, refuses the skill when its path or any ancestor is a symlink or any symlink exists in its tree (`.git` skipped), stages the copy in `<stack>/.ai-stack/stage/` (same filesystem as every target, git-ignored), applies `move` to the directory name and the frontmatter `name:` line, runs the process steps in order with the staging directory as cwd, then swaps with two renames: the old target into a reserved directory in the stage, the staged copy into place. The skill is absent for the moment between them; a crash there leaves the old tree in `.ai-stack/stage/`. If the second rename fails the old tree is renamed back; if that also fails it is kept and its path is in the error. After the process steps the staged directory must hold a regular-file `SKILL.md`, or the install fails before the swap. Every `skills` subcommand clears `.ai-stack/stage/` first. `add` requires `--group`, an existing group, and always installs into `skills/`. It validates the whole file with the new entry and member, the dests and the target with a placeholder commit before `git ls-remote` runs, then resolves the commit, installs, and records the skill with `AddMember` and `PushSkill`; when that edit fails it removes the directory it just installed. A local source is stored canonicalized. `update` rebuilds a missing target without the guard, otherwise checks `git status --porcelain --untracked-files=all --ignored=matching -- <target>` before replacing anything, keeps going after a failed entry, and records every changed entry with one `edit` of `SetSkill` operations at the end. `--ref` changes the tracked ref of the named entries; `--reprocess` falls back to the pinned commit when the unchanged ref cannot be resolved. `status` reports `missing` for an absent target.

`groups.rs` builds the `groups --json` report from `stack.toml` and each member's `SKILL.md` frontmatter (`frontmatter_value` reads plain, quoted and `>` / `|` block values). A budget is `ceil(chars / 4)`, with `chars` summed over the `name` and `description` values of the skills counted; a missing `SKILL.md` counts zero.

The JSON is the contract the Swift app reads ([ADR 0002](../docs/adr/0002-swift-app-drives-the-cli.md)), version 1:

```json
{"version":1,"groups":[{"name":"games","global":true,"includes":["threejs"],"skills":["game-gdd","grill","threejs"],"missing":["grill"],"tokens":812}],"global":{"skills":["game-gdd","grill","threejs"],"missing":["grill"],"tokens":812}}
```

- `version`: the shape's version. A change to an existing field's meaning bumps it; new fields do not.
- `groups`: every group in name order. `skills` is the group's resolved members after includes, sorted. `missing` is the vendored ones among them that `skills update` has not built yet; they count zero tokens and install skips them. `tokens` is the budget of `skills`.
- `global`: the union of the global groups, each skill once, with its own `missing` and `tokens`.

### Codex user skill folder

`Harness::skill_folder` uses `~/.agents/skills` for Codex. Checked on 2026-10-16 against codex-cli 0.160.0 on the Mac: with a throwaway `HOME` and `CODEX_HOME`, `codex debug prompt-input` listed skills from both `$CODEX_HOME/skills` and `$HOME/.agents/skills` in its skill roots table, including a skill that was a symlink to a directory elsewhere. The bundled skill-installer text still names `$CODEX_HOME/skills`. ai-stack links into `~/.agents/skills` only, so a skill never appears twice.

## Fleet

`fleet.rs` loads enabled machines, each with exactly one of `ssh` / `local = true`; login also loads disabled machines and warns when one is selected. It builds each command as words, where path words keep a leading `~/` unquoted for the remote shell and everything else goes through `exec::shell_quote`. `status` requires a 40-hex commit line (otherwise `unreachable: unexpected output`), caches one `ls-remote` per distinct branch and checks ancestry both ways with `git merge-base --is-ancestor` in the local checkout (`behind`, `ahead`, `different`; exit 128, a missing object, is `unknown (fetch first)`); for each reachable machine it also runs `<bin> stray --json` through the same path and prints its counts, or `unavailable (<reason>)` when that fails or does not parse, without affecting the exit code. `update` resolves each machine's branch unless `--branch` is given, skips a detached HEAD, and runs `<bin> --stack <machine stack> update ...` so it pulls the checkout `status` reads. Both `update` and `switch` preserve the remote update's exit 3 as `rebuild needed on <machine>`, keep its rebuild instructions, and exit 1 for the fleet; that machine installed nothing. A local machine without `bin` runs `current_exe()` with the parent's explicit `--config` / `--home`. `switch` runs a dirty check, records `rev-parse HEAD`, runs `fetch <remote> +refs/heads/<B>:refs/remotes/<remote>/<B>`, `switch <B>` with a `switch -c <B> --track` fallback, then `diff --name-only <before switch> HEAD -- cli`. A checkout change under `cli/` reports `now on <B>; rebuild needed on <machine>` and skips update; rebuild there, then rerun the same fleet switch command. Otherwise it runs update per machine; an update failure after the switch says the machine is now on `<B>`. Without `--yes`, `update` and `switch` print and run nothing.

All git, ssh, script and prompt invocations, including `update`'s pull, go through `exec::Exec` (`SystemExec`, stdin closed except for fleet login’s interactive run); fleet and pull tests use `exec::fake::FakeExec`, skills tests use real `git` on local repos. The harness plugin CLIs keep their own `plugins::Runner`, because each command carries per-harness env (`CLAUDE_CONFIG_DIR`, `CODEX_HOME`). Branch arguments go through `exec::check_branch` (a `check_ref` that also rejects `HEAD`, `refs/` and a leading `+`); skill refs through `check_ref`.

`fleet drift [--ignore KEY]... [--json]` queries `<bin> config show --json` with `ai_stack` and `invocation`, preserving explicit local flags and local/SSH path quoting. As with status's stray query, no `--stack` is added: the comparison is between stored effective settings. `[drift] ignore` and each machine's `drift_ignore` are combined at fleet load, then merged with CLI patterns. `drift::drift` compares the union of sorted keys using the same `config::glob` matcher as clean keep lists; only differing ignored keys are counted. Missing sides serialize as null. Every enabled machine is reported; command failures or malformed flat JSON are unavailable, failed process launches or SSH exit 255 are unreachable. Exit 0 requires all reports in sync. JSON is keyed by machine name with state, keys and ignored count, or a failure reason. No timeout, retry or fallback is added.

## Login status

`auth.rs` owns the const `PROVIDERS` descriptor table: id, display name, binary, headless login argv, read-only status argv, parser and optional expiry source (home environment variable, default directory, filename and reader). Add a provider with one table row and its parser, plus parser fixtures. The login column is the sole source of executable login argv; machine and provider inputs only select table entries. No logout command is implemented.

`Report` holds a provider id and `State`. `LoggedIn` alone carries account, expiry, source and optional refresh presence, so logged-out and absent providers cannot carry an expiry. The wire schema flattens these into `id`, `state`, and optional fields inside `{"providers":[...]}`; deserialization rejects unknown fields and invalid state combinations. Provider CLI output is parsed selectively because their schemas may grow. The `Exec` seam includes PATH availability, so tests use fakes without executing provider commands.

Claude uses `auth status --json`, Codex `login status` (including stderr), Cursor Agent `status --format json`, OpenCode `auth list` (ANSI stripped). OpenCode's configured-credential count means configured, not server-validated. Nonzero status exits may still convey a recognized logged-out result; other errors become fixed one-line unknown reasons and never stop the other providers. No timeout or retry is added. Local status exits 0 unless the command itself cannot run, such as an output-write failure.

Expiry readers return only numeric seconds and refresh presence. Codex decodes only its access JWT payload's numeric `exp`; Claude's Linux `claudeAiOauth.expiresAt` is milliseconds and is converted to seconds. File and decode errors collapse to `expiry unavailable`, with no path, token or JSON error included, and are omitted from reports. File resolution honors `CODEX_HOME` / `CLAUDE_CONFIG_DIR` and follows symlinks normally. Claude on macOS has no file reader and never invokes `security`. Cursor and OpenCode have no expiry reader; OpenCode's multiple independent credentials have no single access-token deadline. An expired access token does not override the status command's logged-in state. Refresh presence does not imply a successful future refresh.

`fleet auth [--json]` reuses `ai_stack` and `invocation` from fleet status, including explicit local `--config` / `--home`, custom binaries and remote path quoting; like status's stray query it does not add `--stack`. Each machine returns its local status JSON. Nonzero SSH exit 255 is unreachable, nonzero remote command exits and malformed, incomplete or duplicate-provider reports are unavailable. Raw stdout, stderr and deserialization errors are never echoed. Combined JSON is `{"machines":[{"machine":"name","providers":[...]},{"machine":"old","error":"unavailable (...)"}]}`. Exit 0 requires successful reports from every machine and every installed provider logged in without a known expired token that lacks a refresh token; unknown expiry is allowed, and an expired access token with a refresh token is healthy because the CLI renews it.

This uses the existing SSH transport: BatchMode, the owner's key authentication and LAN hosts. The remote side returns only status, never secrets. Credential files are read locally only to extract expiry and refresh presence; neither raw files nor tokens enter output, serialization or error text. Status checks invoke no keychain command, browser, login, logout or credential refresh.

## Fleet login

`fleet login <MACHINE> <PROVIDER>` resolves a named fleet entry, including disabled entries with a warning, and a provider id from `auth::PROVIDERS`. Unknown names list valid choices. stdin and stdout must both be terminals; the terminal check is injected into `Fleet::login` for fake-only tests.

The provider login column was checked against each installed Mac CLI's `--help`. Installed code was also inspected where help did not establish a headless flow:

| Provider | Login column | Headless mechanism |
| --- | --- | --- |
| Codex | `codex login --device-auth` | `--device-auth` selects device authorization instead of the default localhost callback. |
| Cursor Agent | `env NO_OPEN_BROWSER=1 cursor-agent login` | Login help documents `NO_OPEN_BROWSER`; `env` supplies it as static argv for both local and SSH execution. |
| OpenCode | `opencode auth login` | Its menu offers OpenAI → **ChatGPT Pro/Plus (headless)**. Installed code confirms device authorization and polling. The owner selects the provider and headless method; browser callback methods need a browser on the target. No extra flag is required to enter the menu. |
| Claude Code | `claude auth login` | The owner reports it prints a URL and asks for the code to be pasted back, which works through the ssh pass-through. An earlier inspection of an old installed build (2.1.63) suggested its CLI handler never read pasted input, but the Mac now has 2.1.301 and that inspection was not repeated, so this row is unverified by ai-stack. The follow-up status check reports the outcome either way. |

Before login, `<bin> auth status --json` runs through the existing `ai_stack` and `invocation` path. This delegates the PATH-availability check to the target's `auth::collect`; `not_installed` stops the flow. Unavailable or unreachable status also stops it. The same query runs after the login process exits, and only the selected provider's `Report::text` is printed, preserving account and expiry information. Exit 0 requires both login exit 0 and follow-up `LoggedIn`. Other login exits still get a status check; an SSH exit 255 immediately reports unreachable. A process killed by a signal fails. No timeout, retry or fallback is added.

The channel is SSH. Remote login reuses `invocation`'s single shell-quoted command line and adds `-tt`, yielding `ssh -tt -o BatchMode=yes <dest> -- <line>`. Key authentication and host trust must already work; there are no password prompts. LAN-only is the initial deployment, not an enforced network restriction. Local entries run the static argv directly, without a shell. The `Exec::interactive` seam inherits stdin, stdout and stderr and returns only the exit code (`None` for a signal); ordinary `Exec::run` paths remain captured with stdin closed.

Pass-through lets the provider handle its own URL, prompts, device polling and credential storage without ai-stack scraping provider output or parsing URLs. Login streams are inherited directly by the child: ai-stack never sees an authorization code or token, never captures login output and never supplies a secret to the remote side. The provider exchanges credentials with its authentication service. ai-stack introduces no daemon, callback port, credential store or secret forwarding. Existing status queries still extract only safe expiry metadata as documented above.

Cursor and OpenCode are not handled. Adding a harness needs:

## Lint

`src/lint/` lints only changed lines, with ast-grep (`ast-grep-core`, `ast-grep-config`, `ast-grep-language` 0.51.3, MIT) as a library. Only the TypeScript, Tsx, JavaScript, Rust, Python and Go grammars are compiled in. Agents meet it at commit, through git config hooks that only agent shells carry, after each edit, through one `PostToolUse` hook, and in jj workspaces, through the same hook after jj commit commands and a `PreToolUse` hook before `jj git push`. Nothing blocks a turn.

Shapes:

- `Baseline { Absent, Text(String) }`: a file before the change. `Lines(Vec<RangeInclusive<u32>>)`: 1-based changed lines. `Lines::between(baseline, current)` is the inserted and replaced lines of `similar`'s patience line diff, compared without `\r` and with any expanded `$Id: ... $` collapsed to `$Id$`; an `Absent` baseline changes the whole file. `Lines::widen` adds the innermost function span of each changed line; `Lines::whole` covers the file.
- `Repo { root, project_key }`, found per file with `git rev-parse --path-format=absolute --show-toplevel --git-common-dir`. `project_key` is the parent of the common dir when it ends in `.git`, else the common dir itself, so every worktree of a repository shares one key. A `[[lint.project]]` path is resolved to its repository's key the first time it is compared. Every git call passes `--literal-pathspecs`, `--no-optional-locks` and `-c core.hooksPath=/dev/null`, and reads NUL-separated output.
- `Rule { key: RuleKey { id, language }, source, config: RuleConfig<SupportLang>, base, default_off, fix: Option<Fix>, files, ignores, unless_file, when_file, allow_license_header, allow_in, allow_directives, directives }`. `rules::parse` reads each YAML document as JSON. A document with no `id` and a `directives` list adds regexes to the directive list. Otherwise it removes `files` and `ignores` (compiled with `globset`), reads `metadata.unless_file`, `when_file`, `default_off`, `allow_license_header`, `allow_in`, `allow_directives` and `fix` (`delete-comment` is `Fix::DeleteComment`), then builds one `RuleConfig` per listed language. `Rules::load` refuses one `(id, language)` in two files, then compiles every directive file's list, shipped and local, into one `^\s*(?:...)` regex and gives it to each rule with `allow_directives`. `Rule::is_directive` strips the comment opener (`//`, `/*`, `/**`, `#`, with `!`) and matches the rest.
- `Settings` (resolved `[lint]`, including `skip: SkipLimits` and `skip_alert: SkipAlert`) and `Policy` (settings plus the matching `[[lint.project]]`) decide whether a file is linted, its scope, whether a rule applies to a path, and a rule's severity: `disable`, then `severity`, then `default_off` unless `enable` names it, then the YAML severity.
- `Finding { file, path, rule, severity, line, column, end_line, message, snippet, bytes, fix }`. `file` is the absolute path, `bytes` the matched node's byte range and `fix` the rule's `Fix`; none of the three is serialized. `path` is the display path. `end_line` is the line of the match's last byte, so a Rust doc comment that includes its newline ends on its own line. A finding is kept when `[line, end_line]` intersects the changed lines.
- `scan::Change { path, source, lines, created }` and `scan::Engine::lint(&Change...)`: per file, repository, `Policy`, `git check-attr linguist-generated linguist-vendored` from `Engine::attributes` (`Attributes::Worktree` through a workspace, `Attributes::Index` with `--cached` against the commit's index, or `Attributes::Tree { git_dir, commit }` with `--source <commit>` and `GIT_DIR` set, for a jj store), with `Engine::repo` overriding per-file discovery when set, `ignore` globs, the native `test-file-names` check for a created file (so an empty new file is still checked), stop when no line changed and the scope is not `file`, the rules for that language and path whose file facts hold, then `scan::scan`. `scan::scan` replaces ast-grep's `CombinedScan`, which honours `ast-grep-ignore` comments: it maps each rule's potential node kinds, walks the tree once, matches only nodes that touch the changed lines, and drops matches whose bytes lie inside one of the rule's allowed byte ranges (the licensed leading comment block for `allow_license_header`, and each `allow_in` match) or that are directives. `Change::new(path, source, baseline)` gives a change when the source's lines differ from the baseline's; `Change::read` reads a regular file first.

The CLI diffs the working tree against `git merge-base REV HEAD` through a `Workspace`: a temp directory holding a copy of the index (`git rev-parse --git-path index`; `read-tree HEAD` when there is none and HEAD exists), with every untracked code file from `git ls-files -z --others --exclude-standard` (run on the copy) added by `git add --sparse --intent-to-add --pathspec-from-file=- --pathspec-file-nul`; when the add fails, for example because a listed file vanished, the list is taken again and the add retried once. When the git dir holds a `sharedindex.*` file, the copy is first rewritten as a full index by `update-index --no-split-index` run with `GIT_DIR` set to a private directory holding a copy of `HEAD` and the shared index files, `GIT_COMMON_DIR` set to the real one, so git neither reads nor refreshes the repository's shared index. The copy gets the real index's mtime back so git's racy-entry check still compares same-size edits made in the same second. Every git call in a workspace passes `-c core.splitIndex=false` and `GIT_INDEX_FILE=<copy>`, `GIT_OBJECT_DIRECTORY=<temp>/objects` and `GIT_ALTERNATE_OBJECT_DIRECTORIES=<the repository's objects, C-quoted>`, so new objects and indexes never land in the repository. `git check-attr` runs in a workspace of its own, so it reads `.gitattributes` from the working tree and then from the index copy, which holds the files a sparse checkout leaves out. `git diff --raw -z -M --no-abbrev --ignore-submodules=all <base>`, parsed by `repo::parse_raw`, pairs renames over the whole repository: `A` or an all-zero old id is `Absent`, `R` takes the old path's blob, `D` is skipped, and anything else takes its own old blob. The old blobs are read in one `git cat-file --batch` (`repo::blobs`). A gitlink (mode `160000`) is skipped by the diff, which never asks a submodule for its status. Instead `git ls-tree -r -z <base>` lists the base's gitlinks, and each that is still a checked-out repository at its path is diffed in its own workspace against the commit the parent records, with no merge base. With no `HEAD` commit and `--base HEAD`, `git ls-files -z --cached` on a workspace lists every file as `Absent`. With no PATH, the PATH is the repository root of the cwd. Paths stay `OsStr` bytes from git output to the file read. A PATH that does not exist, a `--base` that `rev-parse --verify` does not resolve to a commit, a `--base` with no merge base with HEAD, or another git error exits 2. `--fix` takes deletion eligibility from HEAD, not the merge base: `Repo::changes(base, true)` also returns a `HeadPrior` (`Repo::head_prior`) holding the removed lines of `git diff -U0 --no-renames --text HEAD` and the per-file baselines of `Workspace::own_changes(HEAD)`, which pairs renames with `-M`, plus, for each gitlink in HEAD that is a checked-out repository, the same taken against the submodule's own HEAD, recursively. It skips files with a worktree `filter` attribute, a skip-worktree or assume-unchanged entry (`Repo::flagged`), more than one link, or `fix::untouchable`, runs `fix::remove_new_plain_comments` on each remaining file's `Fix::DeleteComment` error findings with its HEAD baseline (the file itself when the HEAD diff does not list it) and its `Provenance::written` and `Provenance::moved` sets, writes the result over the file in place only when the file still holds the source that was linted, and lints the fixed files again; a file the fix returns to its baseline drops out of the result.

`provenance::Provenance` (`provenance/` in the state dir) is the record of what the agent's edit tools wrote. `record(path, added)` keeps the trimmed lines that start with `//` or `#`, sorted and deduplicated, and appends `{time, lines}` to `provenance/<key>`, `<key>` being the first 16 bytes of the SHA-256 of `paths::resolve(path)` in hex; it rewrites that file without records older than 7 days when its oldest is, and deletes any file in the directory not modified for 7 days. `written(path)` is the union of the lines of the records from the last 7 days. `record_removed(repo, removed)` and `moved(repo)` do the same for the comment lines an edit removed, keyed by the repository's project key with the prefix `removed\0` in the hashed bytes.

`fix::remove_new_plain_comments(language, source, ranges, prior)` runs inside `catch_unwind`, so a panic leaves the file alone (the commit hooks install a silent panic hook). `Prior { file, removed, written, moved }` carries HEAD's blob, the commit's removed lines and the two provenance sets. It parses the source and groups the comment nodes (`comment`, `line_comment` or `block_comment`) that are `alone` on their lines (only spaces, tabs or `\r` around them) into blocks of consecutive lines (`File::blocks`). A block goes only when every node in it is at one of the reported ranges, `File::plain` and `File::agent_wrote`, and the block `fits`. A trailing `\n` and `\r` in a node are left out of its text. `agent_wrote` needs: its trimmed text is in `written` and not in `moved`; `Prior::holds` is false (no trimmed line with an alphanumeric character is a substring of HEAD's blob or of the removed lines); and its line is outside every hunk of `lines::hunks(HEAD's blob, source)` (patience diff, consecutive non-equal ops merged) whose old lines touch a comment of HEAD's blob. `plain` reads only the source and needs all of: the text starts with `//` or `#`; it holds no `\n`, `\r`, U+0085, U+2028 or U+2029; it starts at or after `code_start`, the first non-empty leaf in depth-first order that is not a comment, inside one, or a shebang (`hash_bang_line`, `shebang`); in Python, it is past line 2; it has no `want "`; `is_doc` is false (Rust `///` but not `////`, `//!`; Go `directly_above_a_declaration`: starts its line, no `block` ancestor, and the run of comments ends one newline above a named sibling); and `looks_like_a_directive` is false (no space after the marker, a first word that does not start with a letter, holds `:` or is all capitals, an `@word` or `$Word` token, or one of `ignore`, `disable`, `suppress`, `noqa`, `pragma`, `codeql`, `deepcode`, `nosec`, `lint`, `format`, `fmt`, `translator` in any case). `fits` needs every node's parent to be one of `statement_containers(language)` (`program`, `statement_block`, `class_body`, `switch_case`, `switch_default`; Rust `source_file`, `block`, `declaration_list`; Python `module`, `block`; Go `source_file`, `block`, `statement_list` and the case kinds) and `stays_multiline` (a top-level kind, `program`, `source_file` or `module`, or at least 2 named non-comment children, a Go `statement_list` counted by its own children), the line above the block not to end with `\`, and in Go not both the line above and the line below to hold a comment that is not alone on its line. `apply` drops the blocks' lines. It walks each run of lines that are blank or dropped: a run with no dropped line is copied; one that starts the file, ends it, follows a line ending in `{`, `(`, `[` or `:`, or precedes a line starting with `}`, `)` or `]` keeps no blank line; any other keeps as many of its blank lines, in order, as its longest stretch of blanks between dropped lines. It returns `None` unless `verified` holds: the new tree has no more `ERROR` or missing nodes than the old one, the leaf tokens outside comments match in kind and text and order, and the presence of a line terminator between each pair of neighbouring tokens, read from each file's own source by absolute byte offsets, matches. `Fixed::removed` lists the deleted comments' ranges, so a caller can name the findings it removed; `Fixed::runs` lists each deleted block's trimmed lines; `Fixed::dropped` holds the 0-based indexes of every source line `apply` left out, blanks included, so `fix::drop_lines` can drop the same lines from other bytes. `fix::remove_runs(language, source, runs)` deletes exactly the blocks whose trimmed lines equal one of `runs`, with `plain`, `fits`, `apply` and `verified` and no `Prior`; `fix::runs` lists every block of a source. `fix::untouchable(rel, source)` is true for a `Code generated`, `DO NOT EDIT` or `@generated` mark in the first 5 lines, a `vendor`, `third_party`, `node_modules`, `testdata`, `fixtures`, `__fixtures__` or `__testfixtures__` path component, or a `.py` file with a line starting `# %%`.

The commit hooks (`commit.rs`). Install gives agent shells `GIT_CONFIG_COUNT=4` and the `GIT_CONFIG_KEY_n`/`GIT_CONFIG_VALUE_n` pairs for `hook.ai-stack-lint.{event,command}` (`pre-commit`) and `hook.ai-stack-lint-post.{event,command}` (`post-commit`), the pre-commit command `[ -x <exe> ] || exit 0; <exe> [flags] lint pre-commit; [ $? -ne 3 ]` and the post-commit command `[ -x <exe> ] || exit 0; exec <exe> [flags] lint post-commit`. `lint pre-commit` refuses with `commit::REFUSE` (3), and the wrapper turns every other exit into 0, so clap errors from an older binary (2), a context error such as a missing `HOME` (1) and a panic (101) let the commit through. git runs a command with spaces through `sh -c`, so the pre-commit hook's parent is that shell and its grandparent the `git commit` process. `commit::Env::from_process` reads the cwd (the worktree root), `GIT_INDEX_FILE` made absolute, `AI_STACK_LINT_SKIP`, `AI_STACK_HARNESS`, a non-empty `TMPDIR`, the hidden `AI_STACK_LINT_ALLOW_TEMP=1` and `AI_STACK_LINT_ALLOW_NO_HARNESS=1` that the integration tests set, and `process::GitProcess::parent_of_this_hook`. That takes the parent, or the grandparent when the parent's command name is not `git` and the grandparent's is, as the git process, and reads the commit process key `<pid>-<start time>` (field 22 of `/proc/<pid>/stat`, or `ps -o lstart=`), `from_shell` (the git process's parent's `/proc/<pid>/comm` or `ps -o comm=` is `sh`, `bash`, `zsh`, `fish` or `dash`, or one of `WRAPPERS`: `timeout`, `env`, `nice`, `nohup`, `time`, `stdbuf`, `ionice`, `chrt`, `setsid`, `flock`; or `_` in the git process's `/proc/<pid>/environ` has base name `git`, which bash, zsh and sh set when they exec their only command), `under_harness` (one of the 16 processes above git, pid 1 included, has the base name of its `/proc/<pid>/comm` or `ps -o comm=`, or of its `/proc/<pid>/exe`, equal to `claude` or `codex`), `amend` (an argument in `/proc/<pid>/cmdline`, or `ps -o args=` split at spaces, that is at least 4 bytes and a prefix of `--amend`, as git accepts abbreviated long options), and the caller's index (`GIT_INDEX_FILE` in that environ: `Default`, `File`, or `Unknown` without `/proc`).

Both hooks return 0 at once unless `Env::agent_commit` holds: `from_shell`, and `under_harness` or `AI_STACK_LINT_ALLOW_NO_HARNESS`. `pre_commit` then writes `markers/<key>` holding `Pending::nothing()`, on every path. A config that does not load, `enabled = false`, or any error outside the fix loop prints `ai-stack lint: skipped (<first line of the error>)` or nothing and exits 0. `open` resolves the top level and `--absolute-git-dir`, and returns no checkout when the git dir holds `MERGE_HEAD`, `CHERRY_PICK_HEAD`, `REVERT_HEAD`, `SQUASH_MSG`, `rebase-merge` or `rebase-apply`, when the project is disabled, or, unless `AI_STACK_LINT_ALLOW_TEMP` is set, when `throwaway` holds: the top level is under `/tmp` or `TMPDIR` (both resolved), or `ignored_by_another_repository`, which runs `git rev-parse --show-toplevel` in the top level's parent, returns false when that repository and the top level have the same resolved `--git-common-dir` (a linked worktree of the same repository), and otherwise runs `git check-ignore -q -- <top level>` in it, every call with the repository variables (`GIT_DIR`, `GIT_INDEX_FILE` and the like) removed from its environment. `Checkout::staged` runs `git diff-index --cached -z -M --no-abbrev <HEAD or the empty tree>` against `GIT_INDEX_FILE` (or `git diff-tree -r -z -M --no-abbrev <parent> HEAD` for post-commit), drops gitlinks, symlinks (`120000`) and paths with no grammar, reads the new and old blobs in one `cat-file --batch`, and drops a new blob that is not UTF-8 or starts with `version https://git-lfs.github.com/spec/`. The rest become `Change`s with the staged content as source and HEAD's blob as baseline. The engine reads attributes from `GIT_INDEX_FILE`.

Error findings split into fixable (`Fix::DeleteComment`) and unfixable. The high-rate reminder comes from `Log::rate` over the events in the window. `Checkout::deletions` then works out every deletion in memory: it takes the files with fixable findings, and `Checkout::rewritable` drops those with a `filter` attribute (`check-attr --cached`), tagged `S` or with a lowercase tag (assume-unchanged) by `git ls-files -v` (`Repo::flagged`), `fix::untouchable`, or whose worktree file has `nlink != 1`. For the rest, `fix::remove_new_plain_comments` takes a `Prior` (HEAD's blob, the removed lines of `git diff-index --cached -U0 --no-renames --text` from `repo::removed_lines`, `Provenance::written` for the file and `Provenance::moved` for the repository). `Checkout::deletions` takes a `Source { base, target, attributes, on_disk }`: `OnDisk::Index` checks flags and links (pre-commit), `OnDisk::Links` only links (jj) and `OnDisk::Ignored` neither (post-commit). `removed_by` names the fixable findings those deletions remove, and `outside_deletions` drops an unfixable finding whose bytes lie inside a deleted comment. The unfixable findings left keep the staged file's line numbers, because nothing is linted again.

With `AI_STACK_LINT_SKIP` holding a non-blank reason and unfixable findings left, those findings are the exceptions; the fixes still run. `Checkout::narrow` counts files, hunks and changed lines (the larger side of each hunk) after the fixes: it pairs the sections of `git diff-index --cached -U0 --no-color --no-ext-diff --no-textconv --no-renames --text` with the names from `--name-only` in order, and for a file with a deletion takes `lines::hunks(baseline, fixed text)` instead of its section, leaving the file out when that is empty. The commit is refused unless the files and the exception count are within `[lint] skip`, and, unless every exception is `test-file-names`, the hunks and lines too. An accepted skip needs `Log::writable` (create the state dir, open `events.jsonl` for append) and the marker rewritten as `Pending { before, Outcome::Skip { findings, reason } }`, `before` being HEAD before the commit; either failing refuses the commit.

Every decision comes before any write. Without a skip, an unfixable finding left refuses the commit with `commit::refusal(findings, "commit")`, which the jj push check shares. The new blob ids come from `hash-object --no-filters --stdin` without `-w`; unless `GitProcess::amend` holds, `Checkout::emptied` refuses when every entry of `git diff-index --cached -z --no-renames --no-abbrev <base>` is an `M` with an unchanged mode whose path is a fixed file whose new id is its old id. When `GIT_INDEX_FILE`'s name is `next-index-*.lock` (a pathspec commit), the caller's lock is `<caller index>.lock` or `<git dir>/index.lock`; when that lock does not exist, no index is touched, the worktree files are rewritten, and the commit is refused with `rerun the same commit`, the only refusal that writes. Then each blob is written with `hash-object -w --no-filters --stdin` and set with `update-index -z --index-info`, and the caller's lock gets the same entry when `ls-files -s` shows it still holds the original blob. The worktree file is rewritten in place only when `lstat` says it is a regular file with one link, its owner-executable bit matches `100755` unless `core.fileMode` is false, and `hash-object --path=<rel> -- <file>` equals the original staged blob; its new bytes are its own bytes with `Fixed::dropped` removed (`fix::drop_lines`), written only when it has as many `\n` as the staged source and `hash-object --path=<rel> --stdin` of the result equals the new blob, so CRLF on disk stays. A file whose index update fails keeps its comments. The exit is 0 with the marker rewritten as `Outcome::Checked` or `Outcome::Skip` and the summary line (`removed N comments in ...; kept M comments (trailing, block, header, edited, tool-read or not written by the agent)`, M being the fixable findings not removed, the files named by `files_named`, at most 5 and then `and N more`). Every output line goes to stderr.

`post_commit` always exits 0. It takes the marker and, with `open` returning a checkout, compares the marker's `before` with HEAD: an unchanged HEAD records nothing, `Outcome::Checked` and `Outcome::Skip` become `checked` and `skip` events with HEAD as `head`, and `Outcome::Nothing` records nothing. This needs no reflog. With no marker, `bypassed` reads `git log -g -1 --format=%gs HEAD`, goes on only for `commit: `, `commit (initial): ` (base `HEAD^1` or the empty tree) and `commit (amend): ` (base `HEAD@{1}`), lints the base against HEAD with attributes from the default index, and runs `Checkout::deletions` on the fixable findings with `diff-tree -p -U0 --text` removed lines, the provenance record and no worktree checks. It records a `bypassed` event naming the unfixable errors and the comments the fixer would have removed, and queues a notice, only when there is one. Any recorded event updates the alert.

Skips and notices (`events.rs`), all under `~/.local/state/ai-stack/lint/`. `events.jsonl` holds one `Event { time, kind: checked | skip | bypassed, repo, harness, head, findings, reason, vcs }` per line, `vcs` being `"jj"` for a jj push and absent otherwise; `Log::record` rewrites the file without events older than 30 days when the oldest is, then appends. `Rate::of(events, repo, since)` counts commits (every event) and flagged (`skip` plus `bypassed`); `Rate::over` needs a flagged commit, at least `min_commits` commits and `flagged * 100 >= percent * commits`. `Log::alert`, run after each recorded event, computes `Rate::over` for the window with and without the repository's newest event and queues a notice when the newest event takes it from not over to over, so the state needs no file of its own. `<key>` is the first 16 bytes of the SHA-256 of `project_key`, in hex. `notices/<key>` gathers a repository's notices, one per line; `Log::take_notice` renames it to a name of its own before reading it and deletes it, so two hooks never deliver one notice twice. `markers/<key>` holds a JSON `Pending { before, outcome }`; entries older than a day are deleted whenever a marker is written.

The edit hook (`hook.rs`) reads `hook_event_name`, `tool_name`, `cwd`, `tool_input` and `tool_response`. A `PreToolUse` `Bash` call whose command `jj::is_push` and whose `cwd` is in a jj workspace goes to `jj::before_push`; any other event but `PostToolUse` returns nothing. A `Bash` call with no queued notice and no jj commit command (`jj::is_commit` and a jj workspace) returns before reading the config. An edit names Claude's `tool_input.file_path` with the lines of `content`, `new_string` and each `edits[].new_string` whose trimmed text is not a line of `tool_response.originalFile`, `old_string` or `edits[].old_string`, or, per file of a Codex patch (`*** Add File:` or `*** Update File:`, renamed by `*** Move to:`), its `+` lines whose trimmed text is not one of its `-` lines; the removed lines are the same computation the other way round. With lint enabled for the file's repository (`jj::locate`, then `Policy::enabled`), `Provenance::record` stores each file's added lines and `Provenance::record_removed` its removed lines under the repository's key (a failure is ignored, which only keeps comments); then each code file the settings lint is read from disk and compared with `HEAD:<rel>` (`Repo::blob_at`, one `cat-file --batch`), and the error findings whose rule has no `fix` become one `additionalContext` line of at most 5 locations and `+N more`. After a jj commit command, `jj::after_commit` gives the `additionalContext` line instead. Notices queued for the repository of `cwd` or of an edited file become the `systemMessage`. Every error is reported on stderr and exits 0.

The jj path (`jj.rs`). `jj::Workspace::find(dir)` takes the nearest ancestor holding a `.jj` directory as the root; its key is the parent of the directory that holds the repo store (`.jj/repo`, or the path a secondary workspace's `.jj/repo` file names), so every workspace of a repository shares one key, and a colocated repository's key equals its git `project_key`. `jj::locate(dir)` prefers the git `Repo` when its root is inside the jj root, else the jj workspace as a `Repo`. Command matching splits the text at whitespace and `;&|()`, finds each word whose base name is `jj`, skips flags and the values of `-R`, `--repository`, `--config`, `--config-file`, `--at-op`, `--at-operation` and `--color`, and reads the first two positional words: `commit`, `describe`, `new`, `squash` or `split` is a commit command, `git push` a push. The skip reason is the value of an `AI_STACK_LINT_SKIP=` assignment in the text (double-quoted, single-quoted or bare).

`fix_range` runs `jj -R <root> --no-pager --color=never --quiet` with `RANGE = latest(mutable() & ::@ & ~empty(), 50)`. It returns nothing when lint is off for the workspace or `roots(RANGE)` is empty. The base is the single commit of `roots(RANGE)-`, else of `fork_point(roots(RANGE)-)`, else an error; jj's all-zero root commit becomes the empty tree. A `Checkout` built with `Git::of_store(root, jj git root)` runs every git call with `GIT_DIR` set to the store. `Checkout::staged(base, Target::Commit(@))` and the engine (with `Attributes::Tree` at `@` and the workspace as `Engine::repo`) give the fixable findings, and `Checkout::deletions` with `OnDisk::Links` the deletions. The plan maps each UTF-8 path to the `Fixed::runs` whose count in `fix::runs` of the file equals their count among the deletions. With a plan, `apply` writes `plan.json` and `fix.toml` to a temp directory under the state dir: `fix.tools.<name>.enabled = false` for each tool named in `jj config list -T name fix.tools` (parsed as TOML dotted keys), and `fix.tools.ai-stack-lint` with `command = [<current exe>, "lint", "jj-tool", "--plan", <plan.json>, "$path"]` and one `root-file:"<path>"` pattern per planned path; then it runs `jj fix --config-file <fix.toml> -s <each root>` and reads `@` again. `lint jj-tool` reads stdin, applies `fix::remove_runs` with the path's runs, and writes the result, or the input unchanged when the plan, path, language or UTF-8 decoding fails. Last, `fix_range` lints `base..@` again and keeps the unfixable errors, sorted.

`after_commit` turns the report into `ai-stack lint: removed N comments in <files>; <at most 5 locations> (fix before pushing)`, and an error into `ai-stack lint: skipped (<reason>)`. `before_push` answers `PreToolUse` JSON: with errors left and no reason, `permissionDecision: deny` with `commit::refusal(left, "push")`; with a reason, a skip whose errors are within `skip.findings` in at most `skip.files` files is allowed and records `skip`, and a wider one is denied; with no errors it records `checked`. Events carry the newest commit of `heads(RANGE)` and `vcs: "jj"`; a skip that cannot be recorded is denied; each recorded event runs `Log::alert`. Lines for an allowed push (the high-rate reminder, the removal summary, the skip line) go back as `additionalContext`, and an error as `ai-stack lint: skipped (<reason>)`, allowed. `lint jj-fix` runs `fix_range` in the cwd and prints the removal and `refusal(left, "push")`, exiting 1 with errors left.

A missing shipped rules directory (`<stack>/lint/rules`) is a load error; a missing local one is not. `Config::exe_flags` holds `--home` and `--config` when they differ from `$HOME` and `<home>/.config/ai-stack/config.toml`, and `--stack` whenever the install was given one or `[stack] path` is relative (`load_config`); the hook entry and both git hook commands carry them. `Config::lint_enabled` is `[lint] enabled`. `install::env_edits(existing, wanted, enabled)` plans the lint environment of one file: with lint on, a foreign `GIT_CONFIG_KEY_n` or a `GIT_CONFIG_COUNT` without keys is an `Err` naming it; with lint off it removes `GIT_CONFIG_COUNT`, every `GIT_CONFIG_KEY_n`/`GIT_CONFIG_VALUE_n` and an `AI_STACK_HARNESS` equal to the harness name when all keys are ai-stack's, and otherwise changes nothing. `plan_hooks` and `plan_codex_env` turn an `Err` into a plan warning and leave that file's environment as it is, so the rest of the plan still applies; the Claude merge runs on a copy of `settings.json` that is kept only on success.

## Safety guarantees

- **Atomic writes with the original mode.** A temp file is created exclusively beside the target (`tempfile::Builder`, random name), given the target's permissions when it exists, written, and renamed over the target.
- **No escaping backups.** Harness homes are normalized at load; a target whose home-relative or absolute backup path has `..`, `.` or no file name is refused.
- **Stale plans are refused.** `Write`/`Remove` compare text, `Unlink` and a repointing `Link` compare the link target, folder-entry actions compare their folder's anchor, `ReplaceWithFile`, `MoveToBackup` and a `Link` over a stray compare an lstat fingerprint of the whole tree, and a new `Link` needs the path to be absent.
- **Skills stay inside the stack.** Manifest paths are validated at load and on every write, so no entry can address a directory outside the stack.
- **No upstream symlinks.** A vendored skill that is, sits under or contains a symlink is refused, so nothing upstream can point a copy or a `move` rewrite outside the stack.
- **Skill replace by rename.** A skill is built in `.ai-stack/stage/` and swapped in by two renames; a failed fetch, `move` or process step leaves the installed skill as it was.
- **Dirty guard.** `skills update` refuses to replace a skill directory with uncommitted, untracked or ignored files unless `--force`.
- **Branch guard.** `update` pulls only into a checkout already on the branch it pulls.
- **Process steps run arbitrary code by design.** Scripts and prompt runners run with the user's permissions in the staging directory.
- **Fleet never forces.** `switch` refuses a dirty checkout and never uses `-f` or `-B`; branch names are validated before they reach any command line.
- **Exact ownership.** Links count as ai-stack's only when the ledger records them with the same target or their target, resolved through the filesystem, lies in the stack or a legacy root; old hooks only when the command resolves to one of the exact old forms for those roots; lint hooks only when the command's first word (unquoted, single- or double-quoted) has base name `ai-stack`, followed by any `--config`, `--home` or `--stack` flags with values and then exactly `lint hook <harness>` (or the older `lint hook <harness> post-edit`); lint environment entries only for `GIT_CONFIG_KEY_n` values that are exactly `hook.ai-stack-lint.event`, `hook.ai-stack-lint.command`, `hook.ai-stack-lint-post.event` or `hook.ai-stack-lint-post.command`; agent files only with the managed marker. In a user skill folder, an owned link a global group wants is kept or repointed, and only an owned link no group wants is unlinked. `--clean` and `stray` never count an owned link.
- **One decision per entry.** Each skill folder is resolved once and each entry classified once, so aliases of one folder never plan two actions for one entry, and `stray` and install conflicts read the same classification.
- **Checkouts are never skill folders.** A skill folder that resolves inside the stack or a legacy root, and a folder entry that holds one, are conflicts, even with `--force`.
- **Apply stays in the planned folder.** A folder-entry action is refused when its folder now resolves elsewhere or is another directory.
- **Stray skills are moved, never deleted.** A directory, file or foreign link at a name the stack links is a conflict. `--force` (or `--clean`, when `keep_skills` does not match it) moves it into the backup as part of the link.
- **The jm marketplace is ai-stack's.** A `jm` plugin the checkout no longer lists is removed on every install. `removed-plugins.json` records `"reinstall": null` and a note naming the last stack commit that lists it. Plugins from other marketplaces are only removed with `--clean`.
- **stack.toml is checked at the boundary.** Every command that reads it validates names, includes, membership and the `skills/` tree first, so a bad file plans nothing. `skills add` checks every argument before the network, and `add` and `update` write `stack.toml` only after a staged skill with a `SKILL.md` is in place, and `add` removes the new skill again when the write fails.

## Constraints the code cannot state

The code has no comments (see `AGENTS.md`), and no name, type or test holds these yet. Keep them when you change the code nearby.

- **`groups --json` is a contract.** The Swift app reads it. A change to a field's meaning bumps `VERSION`; a new field does not.
- **Commands run last in a plan.** The harness CLIs edit files that the plan's actions may touch, so commands run after those actions.
- **`removed-plugins.json` is written before removals,** so the record survives a failed removal.
- **A missing harness home skips the plugin queries.** Nothing is configured yet, and Codex refuses a `CODEX_HOME` that does not exist. The plan assumes nothing is installed, and its file actions create the home before its commands run.
- **`plugin.json` decides the Claude plugin version.** When it and `.claude-plugin/marketplace.json` disagree, Claude Code reports `plugin.json`'s version (one-off probe). Bump both anyway, as `AGENTS.md` says.
- **`~/.agents/skills` is the shared Codex skill folder.** Codex also reads `$CODEX_HOME/skills`, but the stack links into the shared folder (checked against codex-cli 0.160.0).
- **A skill swap needs a reserved name for the old tree.** Renaming a directory onto an empty directory replaces it, so the old tree moves to a reserved name first.
