# Game delivery requirements

These requirements are mandatory at every stage. The stage is whichever stage
skill is running: `games-mini-gdd` (GDD), `games-mvp` (MVP) or `games-final`
(FINAL). Where a stage skill and this contract differ, this contract wins.

## Fidelity

- Satisfy EVERY explicit requirement in the task prompt. List them in
  `REQUIREMENTS.md` and tick each off with where it is implemented.
- Preserve the requested gameplay, visual style and 2D/3D presentation exactly.
- If the prompt says "in the style of X", the game must clearly read as X in
  mechanics, feel and presentation.
- Anything unspecified: make a cohesive, on-theme choice and record it in
  `REQUIREMENTS.md` under "Design decisions".

## Platform

- Playable in a modern desktop browser (latest Chrome) via a local web server.
  No native install.
- No network multiplayer, accounts, API keys, payments or external services.
  Same-device multiplayer only if the prompt asks.
- Works fully offline once installed: bundle all fonts, libraries and assets
  locally. No CDNs.
- Zero console errors on load and during play.

## Tools

- The only AI permitted is Codex and its built-in tools (including built-in
  image generation).
- Computer use or MCPs may drive NON-AI tools (for example Blender, Aseprite,
  ffmpeg, audio editors).
- Do NOT call any other AI model or AI service (image, audio, music, voice,
  code) by any route.
- Log every external tool you drive, and what for, in `BUILD_LOG.md`.

## Assets

- All assets original: generated by you or made with permitted tools. No
  copyrighted or ripped assets, logos or characters.
- Record every asset's file path, how it was made and the tool used in
  `ASSETS.md`.

## Quality bar

- Complete, polished game, not a tech demo. Quality you could publish on
  itch.io.
- Required: title/start screen, clear on-screen controls/instructions, core
  loop, win/lose or scoring, feedback (visual + audio), pause, restart without
  reload.
- Test and fix: movement, collisions, scoring, progression, restart, edge cases
  (window resize, focus loss, rapid input).
- After each significant change: run the game, inspect the rendered output
  (screenshot via Playwright), play the main loop and fix what is broken or
  unclear. Do not stop at the first working version.

## Stage scope

- **GDD**
  - Write `GDD.md` (5-6 paragraphs: concept, core loop, controls, art/audio
    direction, scope/features, risks). No game code.
  - Use image generation to create concept images in 3-4 clearly different
    visual styles that all fit the prompt (for example key screen/gameplay
    mock, character/props, UI). Save to `concepts/<style-name>/`.
  - Summarise each style (look, palette, why it fits, production cost) in
    `GDD.md` under "Concept options".
  - STOP and ask the user to pick a style. Do not proceed until they approve
    one. Record the chosen style in `GDD.md`.
- **MVP**
  - Core loop playable end-to-end; placeholder polish acceptable. Shows the
    intended direction, in the approved style.
  - Host the MVP build on ChatGPT Sites. Record the live URL and deploy date in
    `README.md` ("Live build") and `DEPLOY.md`.
- **FINAL**
  - Everything above, all reviewer feedback applied (see `FEEDBACK.md` if
    present), no known broken or unfinished parts.
  - Update the same ChatGPT Site with the final build (same URL). Verify the
    live version loads and plays, and matches the local build exactly. Update
    `README.md` and `DEPLOY.md`.
- Hosting is in addition to, not instead of, local run: the game must still
  install and run locally from the README.

## Project hygiene

- Everything created (code, assets, docs, scripts, notes, temp files) lives
  inside the project folder.
- Commit the dependency manifest AND lockfile.
- `.gitignore`: node_modules, dist caches, OS junk.
- Scripts: `dev` (local server), `build` (production build if used), `package`
  (creates `submission/<game-name>.zip` with source, assets, README, manifest,
  lockfile, and build output if needed; excludes node_modules, caches,
  credentials, .git and submission/ itself).
- Save a gameplay screenshot to `submission/screenshot.png` from the final
  build.

## README.md (exact sections)

1. **Title + one-line pitch**
2. **Requirements**: runtime + exact version (for example Node 20.x), package
   manager + version
3. **Install**: exact commands
4. **Run**: exact commands + local URL
   - 4b. **Live build**: ChatGPT Sites URL (MVP/FINAL)
5. **Browser tested**: name + version
6. **Controls**: table of input → action
7. **Objective**: goal, win/lose conditions, main interaction
8. **Features**: bullet list mapped to the task prompt's requirements
9. **Setup / sample data**: or "None"
10. **Project structure**: short tree of key folders/files
11. **Tools used**: Codex + every external tool and what it did
12. **Assets**: pointer to `ASSETS.md`
13. **Known issues**: list, or "None"

## Before finishing each session

- Run install → run from a clean state exactly as the README says. Confirm it
  works.
- Update `README.md`, `REQUIREMENTS.md`, `BUILD_LOG.md` and `ASSETS.md`.
- Report: what changed, requirements status, known issues, what to do next.
